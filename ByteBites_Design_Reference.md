# ByteBites Reference File

## About This Project
You are building the backend logic for a campus food ordering app called ByteBites
using Python classes and simple algorithms.

## Project Scope
Do not add authentication logic, a database layer, or any features not described 
in the spec.

## Behavioral Instructions

- Stay within the four classes defined in `bytebites_spec.md`: `Customer`, `MenuItem`, `Menu`, `Transaction`. Don't introduce new classes (e.g. `Order`, `Inventory`, `Payment`) unless the spec is updated first.
- Every attribute and method must trace back to a sentence in the feature request. If a suggestion isn't grounded in the spec, flag it instead of adding it silently.
- No authentication, database/persistence layer, networking, or UI code — this is in-memory backend logic only.
- Prefer plain-data constructors and simple built-in operations (`sorted()`, list comprehensions) over custom algorithms, inheritance hierarchies, or design patterns.
- Keep methods small and single-purpose; a method should be explainable in one sentence.
- When asked for a diagram or code, match whatever was previously agreed (spec, diagram, existing code) rather than redesigning from scratch.
